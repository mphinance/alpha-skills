# Order Lifecycle Safety

Pure markdown. No dependencies, no code to install. These are the rules an order path must own itself; do not assume an external approval gate exists.

## 1. Unique `client_order_id` on every order

- Every order carries a `client_order_id` generated by *your* code, once, before the first send.
- It must be unique per intended order and stable across retries of that same order.
- Persist it (audit log) before sending, so a crash cannot lose it.
- Respect broker length/charset limits: see `references/broker-caveats.md`.

## 2. Same terms vs different terms (REPLAY / ID_REUSED)

| Repeat of an existing id | Correct behaviour | Label |
|---|---|---|
| Same id, **same** terms | Return the first result; do not create a second order | `REPLAY` |
| Same id, **different** terms | Refuse; never mutate or resubmit under that id | `ID_REUSED` |

Implement this in your own layer (compare a hash of symbol, side, qty, type, price, TIF). Do not rely on the broker to do it; broker behaviour varies (see caveats).

## 3. Unknown outcome: reconcile before retry

A timeout, 5xx, dropped connection, or crash after send means the outcome is **unknown**, not failed.

1. Mark the order `UNKNOWN` in the audit log.
2. Look the order up **by client id** (or list recent orders and match). 
3. Found → adopt its status. Not found after the broker's lookup is known consistent → only then may you resend **with the same client id**.
4. Lookup itself fails → stay `UNKNOWN`, alert a human. Never blind-retry.

## 4. Audit before forward

1. Decide (allow/refuse).
2. Write the decision, with the client id and terms, to an append-only audit log **before** forwarding.
3. Forward to the broker.
4. If forwarding raises or times out, append `UNKNOWN` (not `FAILED`) and go to section 3.
5. Redact credentials from log lines.

If the audit write fails, do not forward: fail closed.

## 5. Environment-proof preflight

Never infer paper vs live from config, env var names, base URLs, or account-number shape. Config can be wrong or edited.

- Before the first order of a session, **read the environment back from the broker**.
- Prefer a call that states the environment/capabilities of the session (a session-capabilities call) over a bare auth-status call, which usually proves only that credentials work, not which environment they belong to.
- Compare the broker's answer to the environment the operator intended. Match → proceed. Mismatch, missing field, or any ambiguity → **refuse**.
- Re-run after any credential or endpoint change.
- Whether a given broker exposes such a call is per-broker; see `references/broker-caveats.md`. If none does, treat the environment as unproven and require a human to confirm in a terminal the agent cannot reach.

## Checklist

- [ ] client id generated and persisted before send
- [ ] REPLAY / ID_REUSED handled locally
- [ ] audit entry written before forward; forward failure recorded as UNKNOWN
- [ ] no retry without lookup by client id
- [ ] environment read back from broker, ambiguity refuses
